# ADR 0011: 공유 적용 명세와 장치 로컬 검증 기록으로 Codex 반영 절차 연결

- 상태: 채택
- 채택 근거: [PR #26](https://github.com/1ocate/dotfiles/pull/26) 병합. 작업 0016 재개 시 상태 문구를 병합 이력과 맞췄으며 결정 내용은 유지한다.
- 범위: common, Codex 협업 절차
- 관련 작업: [작업 0015](../work/0015-codex-device-application.md)

## 배경

PR/main의 코드 변경과 다른 장치에서 필요한 설치·loader 연결·재시작이 분리돼 누락된다. 장치마다 생성한 프로필에 공통 동작을 복사하면 일관된 설정 원본을 잃는다. 전체 초기화나 매번 전체 설치는 기존 설정을 손상시킬 수 있다.

## 결정

공유할 것은 공통 설정 원본과 변경별 적용 명세이며, 각 장치의 선택·진행·검증 결과는 Git에 올리지 않는 .local에 둔다. 적용 명세는 기존 목표별 작업 기록에 넣고 PR에서 연결한다. Codex는 [main 변경을 현재 장치에 반영하는 절차](../setup-guardrails.md#main-변경을-현재-장치에-반영하는-절차)를 따른다.

구성요소별 검증 근거와 확인한 소스 기준을 기록하며 전체 main 커밋 수신을 장치 적용 완료로 취급하지 않는다. 상태 기록과 실제 연결·도구·동작을 대조하고 성공한 항목만 완료 처리한다. 장치 프로필은 공통 원본 loader와 의도적인 로컬 설정의 연결 역할을 맡는다. 기존 프로필은 조사·백업 후 필요한 부분만 정리한다.

## 대안과 영향

- 장치별 상태를 Git에서 공유: 오래된 승인/완료 기록의 재사용과 장치 정보 노출 위험 때문에 선택하지 않는다.
- pull 또는 전체 설치 재실행만으로 완료: 추가 연결·재시작·부분 실패를 놓쳐 선택하지 않는다.
- 모든 적용을 도구로 완전 자동화: 후속 구현 대상으로 둔다. 이 변경은 기존 스크립트와 Codex가 수행할 절차를 먼저 고정한다.

기존 로컬 기록 형식과 ADR 0010의 별칭 전용 예외를 유지한다. 새 파일 스키마나 자동 마이그레이션을 도입하지 않는다. 실제 설치/연결 승인은 기존 규칙을 유지한다. 이후 통합 도구를 구현하더라도 이 절차와 완료 기준을 재사용하고, 신규 장치 실기기 검증 전 자동화/지원 완료로 주장하지 않는다.
