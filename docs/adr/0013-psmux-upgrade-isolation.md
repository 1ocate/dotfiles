# 0013: psmux 업그레이드의 실행 파일·세션 데이터 분리

- 상태: 제안
- 작성일: 2026-11-03
- 적용 범위: windows-powershell
- 관련 작업: [작업 0005](../work/0005-psmux-ssh-escape.md)
- 채택 근거: 3.4.0 업그레이드는 사용자가 명시 요청했다. 데이터 분리 구현은 PR 리뷰 대기다.
- 대체 관계: ADR 0003·0006의 Windows 어댑터를 보완한다. 기본 socket 이름과 원본 소유권 검사는 유지한다.

## 배경과 문제

3.3.8에서 Ctrl 입력 이후 ESC 유실과 앱에 마우스 보고 문자열이 입력되는 결함을 재현했다. 공식 3.4.0 후보는 검색·창 이동·입력·휠 격리 대조 검사를 통과했다.
실행 파일만 교체하면 새 클라이언트가 실행 중인 옛 서버에 연결해 문제가 유지될 수 있다. 업그레이드 때문에 사용자의 기존 작업 세션을 종료해서도 안 된다.

## 검토한 대안

- 기존 파일 덮어쓰기·서버 일괄 종료: 진행 중인 작업에 영향을 주므로 제외한다.
- 같은 데이터 경로에서 새 클라이언트만 사용: 기존 서버 버전과 혼합될 수 있어 기본 방식으로 쓰지 않는다.
- 버전별 설치·새 기본 데이터 경로, 기존 pane 유지: 이전 세션 보존과 새 버전 시작을 분리할 수 있어 선택한다.

## 결정과 이유

공식 portable 3.4.0을 SHA256 검증 후 별도 버전 디렉터리에 설치한다. 기본 새 PowerShell은 `PSMUX_DATA_DIR`가 없을 때만 `%LOCALAPPDATA%/psmux/3.4.0`을 선택한다. 사용자의 명시적 데이터 경로는 보존한다.
기존 pane에서는 TMUX의 서버 PID와 실제 프로세스 실행 파일 경로를 확인해 알려진 3.3.8/3.4.0 설치본을 선택한다. 버전 marker 부재만으로 옛 버전을 추정하지 않으며, 알 수 없는 서버나 다른 원본의 pane은 자동 채택하지 않는다.
연결할 세션의 `#{version}`과 선택 실행 파일 버전을 비교해 명시적 공유 데이터 경로에서도 버전 혼합을 거절한다.
사용자 PATH는 새 설치 경로를 앞에 두되 기존 경로를 백업·보존한다. 이미 실행 중인 프로세스의 PATH·서버는 변경하지 않는다.

## 영향과 재검토 조건

새 `mux` 목록에서 옛 데이터 경로의 세션은 보이지 않을 수 있지만 삭제되지 않는다. 복구는 기존 데이터 경로와 3.3.8 실행 파일을 사용한다. 새 탭과 기존 pane의 버전을 상태 조회에서 구분한다.
3.4.0은 서버 시작 설정을 전역 환경에만 두고 CLI 인수의 따옴표·`\;` 처리가 3.3.8과 다르다. 원본 소유권은 세션 값이 없을 때 전역 값으로 확인한다. 일부 바인딩만 담은 파일의 `source-file`은 두 버전 모두 설정의 다른 바인딩을 초기화하므로 사용하지 않고, 바인딩은 원본 설정에만 둔다([ADR 0015](0015-psmux-project-popup.md)).
프로필은 기존 공통 원본 loader를 유지하며 독립 복사본을 만들지 않는다. macOS·WSL·Linux의 설치·셸·tmux 동작은 바꾸지 않는다.
물리 키·IME·장기 마우스 등록 및 실제 Codex 사용은 격리 검사와 별도로 확인한다. upstream 후속 입력 회귀 수정은 별도 버전 검토 대상으로 남긴다.
