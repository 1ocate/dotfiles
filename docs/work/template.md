# NNNN: 작업 목표

- 상태: 계획
- 요청·배경: 작업이 필요한 이유와 근거
- 시작일: YYYY-MM-DD
- 기준: main 커밋, 작업 브랜치
- 실행 환경: 환경 ID
- 적용 범위·비대상: 대상 파일·기능과 제외 사항
- 관련 ADR: 링크 또는 새 결정이 필요하지 않은 이유
- 관련 PR: 제출 후 갱신

## 분석과 미확인 사항

현재 동작·문제와 추가 확인이 필요한 내용.

## 계획과 완료 조건

단계별 산출물, 검증 범위·방법과 완료 조건. 계획 변경 시 이유를 로그에 남긴다.

## 다른 장치 적용 명세

설정 동작을 바꾸는 PR은 아래 항목을 작성하고 PR에서 이 절을 연결한다. 문서 전용 변경은 실제 장치 적용 불필요와 그 이유를 쓴다. 자세한 기준은 [장치 반영 절차](../setup-guardrails.md#main-변경을-현재-장치에-반영하는-절차)를 따른다.

| 항목 | 내용 |
| --- | --- |
| 구성요소·대상 환경 | 식별 가능한 구성요소 이름, 적용/비대상 환경, 필수·선택 여부 |
| 변경 원본·선행 조건 | 관련 경로, 필요한 도구·버전·선택 기능, 이전 동작 |
| 변경 종류 | 원본 갱신만 / 설치·연결 추가 / 기존 설정 이전 중 해당 항목 |
| 사전 확인·적용 | 실제 존재하는 점검·적용 스크립트/명령과 실행 순서, 기존 설정·명시값 보존, 재실행 동작 |
| 검증·완료 판정 | 기능별 검사와 기대 결과, 정적/모의/실기기 구분, GUI·새 셸·재시작 필요 여부 |
| 복구·로컬 기록 | 백업과 복구 방법, 해당 장치 기록 위치, 부분 실패/검증 필요 시 남길 작업 |
